## 1. 🔍 발견된 복잡도 및 기존 엔진의 미흡 사항

### 1.1. 표(Table) 컬럼 너비 균등 분할로 인한 레이아웃 왜곡 버그
- **문제 현상**:  
  기존 코드에서 표의 각 열 너비를 단순 균등 분할(`colWidth = Math.floor(totalWidth / colCount)`)함에 따라, 5열 표(구분, 항목, 산출내역, 금액, 비고)의 경우 넓은 공간이 필요한 '산출내역' 열이 20%만 할당되어 단어가 2~3글자 단위로 깨지며 세로로 길게 늘어지는 심각한 타이포그래피 왜곡 발생.
- **원인 분석**:  
  공식 정부/대학 창업지원 공문서는 열의 성격에 따라 비대칭 비율(예: 항목 15%, 내용 40% 이상)을 엄격히 적용해야 하나, 텍스트 길이에 따른 가중치나 명시적 너비 지정 기능이 부재했음.

### 1.2. 다차원 셀 병합(rowSpan/colSpan) 및 헤더 음영(borderFill) 누락
- **문제 현상**:  
  [붙임 1] 지원신청서의 '동아리 개요'(아이템명 5칸 병합), [붙임 3-1] 지원금 사용계획서(아이템 개발비 2개 행 병합, 활동비 4개 행 병합, 합계 3개 열 병합)와 같은 관공서 표준 서식이 모두 1x1 단일 셀로 평탄화되어 양식이 완전히 틀어짐.
- **원인 분석**:  
  HWPX OWPML 표준의 `<hp:tc>` 태그 내 `<hp:cellSpan colSpan="..." rowSpan="..."/>` 및 가상 2D 그리드 추적기가 구현되어 있지 않았고, 음영 배경(`#F2F4F7`)을 위한 `<hc:fillBrush>` 스타일 정의가 `header.xml`에 누락되어 있었음.

### 1.3. `<hp:secPr>` 누락으로 인한 125건의 문서 구조 경고 (Studio Warning)
- **문제 현상**:  
  생성된 HWPX 문서를 한울 위지윅 에디터(Studio)에서 열었을 때 `"문서 구조 경고 125건. 표시와 저장 결과를 확인해 주세요."` 경고 발생.
- **원인 분석**:  
  KS X 6101 표준에 따르면 HWPX 문서의 첫 번째 문단(`<hp:p id="0">`)은 반드시 섹션 속성(`<hp:secPr>`)을 포함하여 용지 크기(59528 HWPUNIT), 여백(좌우 8504, 상하 5668/4252), 페이지 테두리, 각주/미주 규칙을 선언해야 함. 단순 텍스트 문단으로 치환하여 저장 시 렌더러가 용지 레이아웃을 추정하지 못해 경고가 대량 발생함.

### 1.4. 증빙 스크린샷(BinData) 임베디드 엔진 부재
- **문제 현상**:  
  외주용역 검수요청서【서식 3】 및 결과보고서【서식 5】의 필수 요건인 실물 개발 화면 캡처를 HWPX 본문에 삽입하지 못함.
- **원인 분석**:  
  이미지 바이너리를 ZIP 내 `BinData/` 디렉토리에 패키징하고, `Contents/content.hpf` 매니페스트(`<opf:item ... isEmbeded="1"/>`)에 등록하며, `<hp:pic>` / `<hc:img>` 개체 속성을 생성하는 파이프라인이 미구현 상태였음.

### 1.5. Antigravity MCP 연동 체계 누락
- **문제 현상**:  
  AI 에이전트(Antigravity) 환경에서 HWP/HWPX 분석 및 생성 도구를 호출할 수 있는 글로벌 MCP 등록 설정(`~/.gemini/config/mcp_config.json`)과 로컬 스키마 정의가 연동되어 있지 않았음.

## 2. 🚀 신규 추가 및 고도화된 기능 명세

### 2.1. 표준 준수 HWPX 문서 빌더 (`src/core/hwpx-builder.ts`)
- **A4 최적 인쇄 규격(42520 HWPUNIT) 기반 명시적 컬럼 너비 지정**:
  - `colWidths: number[]` 배열을 통해 표의 각 열 너비를 픽셀 단위로 정밀 제어.
- **2D 가상 점유 그리드를 활용한 완벽한 `rowSpan` & `colSpan` 처리**:
  - 병합된 셀이 차지하는 가상 좌표(`grid[r][c] = true`)를 추적하여 OWPML 스펙에 일치하는 `<hp:cellAddr>`, `<hp:cellSpan>`, `<hp:cellSz>` 자동 계산.
- **관공서 표준 헤더 음영 및 테두리 스타일 지원**:
  - `header.xml`에 `borderFill id="4"`(배경 `#F2F4F7`, 테두리 `0.12mm SOLID`)와 문단 정렬 `paraPr id="20"`(CENTER), `id="21"`(RIGHT) 동적 주입.
- **공식 섹션 속성(`<hp:secPr>`) 기본 탑재**:
  - 첫 문단에 온전한 `<hp:secPr>`를 보존 주입하여 Studio 문서 구조 경고 0건 달성.
- **페이지 나누기(`<hp:p pageBreak="1"...>`) 지원**:
  - 다면 서식([붙임 1], [붙임 2], [붙임 3-1], 과업지시서, 계약서 등)을 페이지별로 깔끔하게 분리.
- **BinData 임베디드 이미지 파이프라인**:
  - 스크린샷 파일을 자동 읽어 `BinData/image_N.png`로 압축 패키징하고, `content.hpf` 매니페스트 등록 및 `<hp:pic>` 그래픽 개체 삽입 완료.

### 2.2. 마크다운 to HWPX 실시간 컴파일러 (`src/core/markdown-compiler.ts`)
- GFM 마크다운의 제목(`#`, `##`, `###`), 표(`| ... |`), 인용구(`>`), 리스트(`-`, `1.`), 이미지(`![alt](path)`), 페이지 구분자(`<pagebreak>`, `---`)를 분석하여 HWPX 문서로 직접 변환.
- 표의 열 수에 따라 최적의 관공서 표준 너비 비율(2열: 25%/75%, 5열: 15%/18%/41%/13%/13%, 6열: 14%/22%/15%/18%/21%/10%) 자동 적용.

### 2.3. MCP 도구 10종 확장 및 Antigravity 글로벌 등록
- 신규 MCP 도구 2종 추가:
  1. `hanul_markdown_to_hwpx`: 마크다운 문서를 HWPX로 원클릭 무손실 컴파일.
  2. `hanul_create_styled_document`: 고급 서식(표, 음영, 병합, 이미지) 기반 전문 HWPX 생성.
  3. `hanul_create_document`: `HwpxDocumentBuilder` 기반으로 전면 리팩토링.
- `~/.gemini/config/mcp_config.json`에 `hanul-hwpx` 등록 완료.
- `~/.gemini/antigravity/mcp/hanul-hwpx/` 디렉토리에 10개 도구 스키마 JSON 전수 배포.
